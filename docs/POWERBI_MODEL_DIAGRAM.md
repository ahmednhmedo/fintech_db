# Power BI Model View — Expected Schema Diagram

What the model should look like after you import the tables and set the relationships.
It's a **star schema** (fact in the middle, dims around it) with two **outriggers**
(`dim_location`, `dim_date` reused by dims) and one **role-playing** dimension (`dim_account`
linked twice from the fact).

```
LEGEND
  PK / 🔑   primary / surrogate key (the "one" side)        ═══►  ACTIVE relationship   (solid)
  FK        foreign key on the fact / dim                   ┄┄┄►  INACTIVE relationship (dashed)
  *:1       Many (fact) → One (dim)                          all relationships: Single filter direction (dim → fact)
```

## Outriggers (dims that sit *behind* `dim_account` / `dim_merchant`)

```
   dim_account ──location_key──►┐                    ┌◄──location_key── dim_merchant
                          *:1    │                    │   *:1
                                 ▼                    ▼
                          ┌────────────────────────────────┐
                          │        dim_location            │   ← shared geo: a location slicer
                          │  🔑 location_key (SK)          │     filters BOTH accounts & merchants
                          │  city / governorate / country  │
                          └────────────────────────────────┘

   dim_account ──signup_date_key┄┄►┐                 ┌┄◄──opened_date_key── dim_merchant
                     (INACTIVE)     │                 │   (INACTIVE)
                                    ▼                 ▼
                          ┌────────────────────────────────┐
                          │        dim_date 📅             │   ← keep ONLY fact.date_key active;
                          │  🔑 date_key                   │     signup/opened links stay dashed
                          └────────────────────────────────┘     so a date slicer filters TXNS only
```

## What "correct" looks like at a glance
- `fact_transactions` in the center with **8 lines** going out (7 dims + the 2nd dashed line to `dim_account`).
- **Two solid lines to `dim_account`?** No — **one solid** (`account_key`) and **one dashed** (`peer_account_key`).
- `dim_location` has **two arrows in** (from `dim_account` and `dim_merchant`) — it's the shared outrigger.
- `dim_date` has **one solid arrow in from the fact** and **two dashed** from `dim_account`/`dim_merchant`.
- `dim_date` shows a small **calendar/Date-Table** marker after you "Mark as Date Table" on `full_date`.
- Every line shows **`*` on the fact/child side and `1` on the dim side**, arrow pointing **into the fact** (dim filters fact).
